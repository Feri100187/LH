# M0.1 跨帧率计时修复

范围：在 `31881e478c0c2a1e6d9ea6fb00c11efdbeb4bf48` 上修改必要的运行计时与验证工具；不进入 M1。实际结果见 `acceptance.md`，引擎调用链与哈希见 `physics-semantics.md`。

## 根因与处理

### 移动单位

安装版 LayaAir 3.4.1 的 `CharacterController.move()` 原样转发给 Bullet `setWalkDirection`，同一向量在每个固定子步执行。旧逻辑传入 `velocity * renderDelta`，15 FPS 时被一轮的多个子步重复使用，高于60 FPS时反而不足。

现在从运行实例的 `physicsSimulation.fixedTimeStep` 读取 `h`，核对 `Scene3D.physicsSettings` 的步长和子步数，再提交 `velocity * h`。没有硬编码渲染帧率、没有修改项目的 h 或 maxSubSteps。行走1.65、奔跑4、跳速6.5、方向步程缩放、归一化和低幅度摇杆输入均保持原值。

### 间断与物理欠账

单调墙钟和引擎delta任一超过250ms，或窗口失焦/隐藏时，清空按键、摇杆、扳机、待处理跳跃/点射，提交零移动。恢复需要新的输入，OS自动重复按键不能重新激活已经清掉的按键。

3.4.1的2D根脚本更新先于Scene3D物理更新。独立适配函数把当前场景 `_physicsStepTime` 写为当帧delta的相反数，随后引擎自己的累加恰好归零，从而丢弃本帧及旧积压。版本由构建入口固定，运行时检查字段/数值和两层配置，源码契约覆盖普通及Profiler路径。这里没有等价公共API，适配器仅封装这一已核实的私有字段。

正常帧保留分数子步；积压超过当前子步预算加一个h时截到本帧预算，避免长期超载后追赶。当前配置4子步、h=1/60，在持续低于约15游戏更新/秒时可以减速而不积欠账；这不是对任意低帧率都保持目标速度的承诺。大卡顿丢弃输入和位移属于明确的安全边界，不修改目标移动速度。

### 射击和释放

PlayerAvatar接收本帧 `performance.now()` 单调时间。首发在实际更新帧触发，后续按原约0.2秒期限调度。一帧最多产生一发，错过的期限跳过；大于250ms的时间间断取消旧周期。合法帧间短点可以保留一个请求，释放持有扳机清除旧请求；取消一个指针时若还有其他合法扳机来源，保留原截止时间，防止重新首发缩短间隔。

`shotEvents`保留最近256条 `{id, atMs}` 实际更新时刻，返回副本。它不把理想截止时间伪装成发射时间。原射击剪辑、上身层、八方向动画和角色资源未更换。

输入释放通过真实输入回调同步到Avatar；HUD使用单调时间刷新并在释放/取消时公布当前状态。数值验收直接读原游戏状态和物理后位置，独立统计原onUpdate调用，因此HUD刷新本身不能让移动或射击断言通过。

## 验证入口

`npm test -- --ide <3.4.1安装目录>` 包含原测试及新增帧率/射击数值回归。子步模型明确标记为逻辑测试，不能代替真实Bullet运行。恢复旧公式的内存负对照和取消指针的失败尝试均保留。

重新构建Web后，`node tools/serve.cjs --m01-probe --root release/web --port 18771` 仅在开发响应中加入测试面板，发布bundle不包含测试脚本。真实页面通过Render.frameInterval限制更新门限，不替换时间或timer.delta；每项记录实际onUpdate帧率。

平地数值起点为[0,1.88,100]，当前碰撞地面Y=.8、附近无障碍。只在各段开始显式设置测试起点，测量阶段不传送。位置由原cameraFollow.follow执行后采集，发射读真实事件。距离误差界限为目标距离3%加两个实际物理步；0.4～0.65秒长窗速度上界为配置速度的105%加一个物理步量化误差。前后使用同一断言，不以动画切换通过替代数值通过。

释放时序sidecar分别保留直接输入、Avatar扳机和原HUD版本；路线/跳跃/相机sidecar只从旧记录提取坐标作为配方，不使用旧PASS作为当前结果。真实手机、多指硬件、GPU专用计时与未执行的路线另列未验证。
